# GraphSieve

**Reducing False Positives for ML-based Web Attack Detectors via Topological Community Discovery**

GraphSieve is an unsupervised post-detection filtering framework that removes false-positive (FP) alarms generated by machine-learning-based web attack detectors. Instead of scoring each alarm in isolation, GraphSieve models the *topological connectivity* among alarms: it constructs a weighted $k$-nearest-neighbor alarm graph, partitions alarms into communities with a resolution-controlled Leiden algorithm, and identifies FP-dominated communities through adaptive, profile-based geometric discrimination. It requires no access to the detector's internals and no ground-truth labels at inference time.

## Pipeline

The framework consists of three sequential modules:

1. **Feature Distillation** — unsupervised variance-based feature selection. Each feature is min-max normalized and log-compressed; near-constant dimensions that carry no structural information are removed, producing a distilled space for graph construction.
2. **Topology-aware Alarm Community Discovery** — alarms are linked to their $k$ nearest neighbors with edge weights inversely proportional to distance; a resolution-controlled Leiden algorithm partitions the graph into structurally coherent communities, and micro-communities below a size threshold are merged into their nearest core community.
3. **Profile-based Adaptive FP Detection** — each community is profiled with intrinsic geometric statistics (size, intra-cluster distance, density, neighborhood sparsity). A small pool of candidate signal-direction rules is maintained, and the most discriminative rule plus a sample-level blending ratio are selected on a held-out validation split. The operating threshold is chosen by maximizing the cost-effectiveness ratio (CER) subject to a minimum filtering volume and a stability floor, then frozen for online use.

```bash
pip install numpy pandas scipy scikit-learn python-igraph leidenalg torch tqdm
```## Data Format

Each experiment consumes an **alarm set** produced by an upstream detector — a JSON list of records, where every record is an alarm (the detector predicted "malicious"):

```json
[
  {"y_true": 0, "y_pred": 1, "features": [0.12, 47.3, ...]},
  {"y_true": 1, "y_pred": 1, "features": [0.98, 12.1, ...]}
]
```

- `y_true`: ground-truth label (0 = benign, 1 = malicious).
- `features`: the traffic feature vector used by the detector.
- All `y_pred == 1` (alarms only). `y_true == 0` are false positives; `y_true == 1` are true positives.

Alarm sets are organized under a data directory as `{dataset}-{type}-{model}/split_seed{seed}/alert.json`. To reproduce the alarm sets used in the paper from the public raw datasets, use `generate_fp.py` (see below); otherwise, any alarm set in the above format can be fed directly to `batch_experiment.py`.

## Quickstart

### 1. Run the main experiment

```bash
# Run all experiments under ./fp_data, results written to ./batch_output
python batch_experiment.py

# Subset
python batch_experiment.py --datasets Malicious_TLS kdd --models svm

# Custom data directory / output directory
python batch_experiment.py --fp_data_dir ./data --output_dir ./results
```

Each run follows the paper's protocol: the alarm set is stratified-split into validation (30%) and test (70%); clustering hyper-parameters, the discrimination rule, and the blending ratio are selected on the validation split (filtering-curve AUC), the threshold is selected by max CER subject to `R.FPR >= 0.3` and `R.TPR >= delta` (`delta = 0.02`), and the frozen configuration is then applied to the test split. Baselines (Isolation Forest, KNN, LOF) are tuned with a light hyper-parameter search on the same validation split.

Results are appended incrementally to `batch_output/batch_results.csv` (per-run rows are safe to resume).

### 2. Run the ablation study

```bash
python ablation_v2.py --output_dir ./ablation_output
```

Five variants are compared against the full model: `Repl. DB` (DBSCAN instead of graph + Leiden), `w/o FS` (no feature distillation), `w/o AD` (fixed discrimination rule instead of adaptive selection), and `w/o Blend` (no sample-level refinement). The full-model row reuses the results of the main experiment.

### 3. Generate alarm sets from raw datasets (optional)

```bash
# point --data_root to the directory that contains the four raw datasets
python generate_fp.py --data_root /path/to/raw/datasets \
    --dataset_name ids2017 --model_type svm --split_seed 16
python generate_fp.py --data_root /path/to/raw/datasets \
    --dataset_name Malicious_TLS --model_type n3ic --split_seed 24
```

Supported datasets: `ids2017`, `unsw-nb15`, `kdd`, `Malicious_TLS`; supported detectors: `svm`, `ae`, `n3ic`. The raw datasets are publicly available; see the corresponding papers for acquisition details. Expected CSV layouts:

| dataset | expected files under `--data_root` |
|---------|------------------------------------|
| ids2017 | `IDS2017/MachineLearningCVE/*.csv` |
| unsw-nb15 | `unsw-nb15/CSV Files/UNSW-NB15_{1,2,3,4}.csv` |
| kdd | `kdd/*.csv` |
| Malicious_TLS | `Malicious_TLS/*.csv` |

## Metrics

- **R.FPR** — fraction of false positives removed by the filter.
- **R.TPR** — fraction of true positives (attacks) mistakenly removed.
- **CER** — cost-effectiveness ratio, `CER = R.FPR / max(R.TPR, delta)` with `delta = 0.02`; higher is better.
